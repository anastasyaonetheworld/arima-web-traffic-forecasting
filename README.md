# ARIMA Web Traffic Forecasting

Прогнозирование ежедневной посещаемости страниц Википедии с использованием модели ARIMA и автоматического подбора гиперпараметров.

## Данные

Используется датасет [Web Traffic Time Series Forecasting](https://www.kaggle.com/competitions/web-traffic-time-series-forecasting/data).

- Анализируются 10 страниц Википедии.
- Для каждой страницы используются последние 400 дней наблюдений.
- Последние 30 дней выделяются в тестовую выборку.
- Пропущенные значения заполняются предыдущим значением, а оставшиеся — нулём.

Датасет не включён в репозиторий. Его можно поместить в `data/train_1.csv.zip` или `data/train_1.csv`. Если файл отсутствует, скрипт пытается скачать архив через `kagglehub`.

## Подбор модели

Для каждой страницы отдельно перебираются параметры ARIMA:

| Параметр | Диапазон |
| --- | --- |
| `p` — порядок авторегрессии | 0–8 |
| `d` — порядок дифференцирования | 0–2 |
| `q` — порядок скользящего среднего | 0–8 |

Всего **243 сочетания `(p, d, q)`**. Для каждого сочетания дополнительно сравниваются:

- исходный ряд (`raw`) и преобразование `log1p`;
- вся доступная история и последние 240 дней.

Выбор производится по средней **RMSE** на трёх последовательных валидационных интервалах по 30 дней. Тестовые наблюдения при подборе параметров не используются.

## Оценка прогнозов

Для выбранной модели строятся два вида прогноза:

1. **Fixed forecast** — прогноз сразу на весь тестовый период, без добавления новых наблюдений.
2. **One-step-ahead** — однодневный прогноз с последовательным добавлением фактических наблюдений без повторного обучения параметров модели.

Оба подхода оцениваются на горизонтах **15 и 30 дней** с помощью метрик **MAE, RMSE и sMAPE**. Прогнозы ограничиваются снизу нулём, поскольку посещаемость не может быть отрицательной.

## Установка и запуск

Требуется Python 3.10+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python arima_forecasting.py
```

Поместите датасет в папку `data/`, если он не скачивается автоматически. Полный перебор может выполняться долго: скрипт проверяет до 972 вариантов на страницу (`243 × 2 преобразования × 2 длины истории`), причём каждый вариант оценивается на трёх валидационных интервалах.
